# evals/ — the measurement harness

Model quality is a number on every commit, not an opinion in a conversation.

- `run.py` — one entry point for every measurement named in the spec.
- `golden/` — frozen evaluation data. Never used for training, tuning, threshold selection
  or augmentation. Read `golden/README.md` before touching anything in it.
- `out/` — generated metrics. Gitignored, regenerated by the gate, never hand-edited.

## Why unimplemented suites exit non-zero

Every requirement in the spec claims a command produces its number. Until that command
really measures something, the claim is false — and it has to be false *loudly*. A suite
that printed a placeholder number would let a requirement look measured when nothing
measured it, which is the exact failure the harness exists to prevent.

So `make eval-dedup` today writes `evals/out/dedup.json` with `status:
"not_implemented"` and exits 1. It stops exiting 1 the week someone implements it, and not
before.

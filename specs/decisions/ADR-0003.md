# ADR-0003 — Error budget: FAR ≤ 1%, FRR ≤ 10%

**Status** accepted · **Date** 2026-08-15 · **Decider** PawChain ID architect

## Context

A single similarity threshold controls both error rates in opposite directions. Raise it
and wrong matches fall while failed scans rise; lower it and the reverse. There is no
setting where both are zero. The threshold therefore cannot be chosen by maximising
accuracy. It is chosen by deciding which harm the system is allowed to cause, and how
often.

This system can accuse someone. That makes the choice a design decision with a moral
component and a number attached, and it belongs in the spec before any model exists —
because after a model exists, the temptation is to report whichever number looks best.

## Options considered

1. **Symmetric budget** (FAR ≈ FRR ≈ 5%): treats the two errors as equally bad. They are
   not.
2. **FAR ≤ 1%, FRR ≤ 10%**: strongly prefers failed scans over wrong matches.
3. **FAR ≤ 0.1%, FRR unbounded**: near-eliminates wrong matches at the cost of a system
   that frequently fails to recognise cats it has enrolled.

## Decision

Option 2. FAR ≤ 1% and FRR ≤ 10%, both measured at the same operating threshold on
identities never seen in training (REQ-004, REQ-005).

## Because

The two errors are not worth the same.

- A **false reject** means a user scans their cat again. The cost is annoyance, measured
  in seconds.
- A **false accept** means an innocent household is accused of abandonment and loses a
  deposit. The cost is injustice, measured in money and reputation.

I would rather inconvenience ten people than falsely accuse one.

Option 3 was rejected because an unbounded FRR is not free: at enrolment it produces the
littermate lockout (threat model row 10), and a system that fails to recognise enrolled
cats loses the honest users first. The asymmetry is real but it is not infinite.

## Consequences

- **1% of matches will be wrong, by design.** That is written down, and it is why every
  penalty path passes through a human adjudicator (REQ-010) and why an appeal window
  exists at all (REQ-015). The appeal window is sized from this number, not from
  convenience.
- The operating threshold is a measured output of Week 3, not a hand-chosen constant. The
  0.62 in REQ-007 is a placeholder pending that measurement (OQ-001).
- Any model change that improves FRR by loosening FAR past 1% is rejected regardless of
  headline accuracy.
- If the measured curve cannot deliver both numbers at any single threshold, the correct
  response is to report that and revise the budget in writing — not to report the better
  of the two numbers.
